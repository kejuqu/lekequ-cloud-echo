1. 创意与玩法
创作灵感：把「登山」这一朴素的向上动作，和「汉字成语」这一最中国的文化符号结合在一起。传统跑酷游戏只有躲障碍，我们希望玩家每爬一步都在「读懂一座山」——山顶红旗上的四字成语，就是这一关的答案，也是这一路的谜题。

核心玩法：一款 3D 低多边形（Low Poly）网页端文字解谜登山冒险游戏，基于 WebGL（Three.js）浏览器直接游玩，无需下载客户端，PC 键鼠与手机虚拟摇杆双端一套代码自适应。玩家攀登 18 座主题山峰（春、夏、秋、冬与四季回响终章）：
· 收集成语：每关红旗显示一个目标四字成语，沿路散落该成语的 4 个汉字字块，集齐后文字锦囊显形，拾取后携完整成语到山顶红旗处校验一致方可通关；未集齐时红旗提示缺字。
· 凹坑蓄力蹬跳：平地只能小跳；踩入凹坑在完美窗口内蹬跳可获得超高弹跳，是到达高处岩点的唯一途径，过早/过晚都会滑落——痛苦感与爽感并存。
· 反向减速带：下坡铺设反向推力带，不能刹车只能借势：冲坑弹飞后控好落点接上上坡加速段，用下坡势能冲最难的上坡。
· 打野兽：弓箭（无限弹药低伤害）与手枪（有限弹药高伤害）击杀食人虫、幼龙、恶龙；第 5 关为终焉恶龙 BOSS 战。
· 风险规则：触碰炸弹直接爆炸重置本关；被野兽击中跌落山脚重开；大招为充能型冲击波，击杀/拾取/过检查点积攒能量，危急时脱困。

作品亮点：
· 玩法耦合：收集、物理借势、射击、解谜四种机制互相咬合——坑借弹跳、带借势能、字借路线，关卡设计围绕「路线规划」展开。
· 双端自适应：PC（WASD/鼠标/Shift 冲刺）与手机（左下虚拟摇杆 + 右下功能按钮组 + 右侧滑动转视角）一套代码。
· 氛围完整：低多边形山岳 + 季节雾效 + 雪地脚印 + AI 生成的动态配乐与音效，18 个关卡（5 大关 × 多难度变体）。

2. 创作过程
主要开发步骤：
1) 需求与设计：先写完整设计文档（关卡机制、双端操作、UI、存档规则），确定「成语校验」为核心闭环。
2) 架构分层：将纯逻辑（rules.ts / simulation.ts / levels.ts）与渲染（game.ts）严格分离，规则层不依赖 Three.js，为测试铺路。
3) 核心玩法迭代：先做凹坑蹬跳与体力/冲刺系统，再接入反向减速带、武器射击、怪物 AI 追击（chase.ts）、BOSS 阶段机（boss-effects.ts）、水火机关（fire-water.ts / water-timing.ts）、传送门与幸运大转盘奖励。
4) 移动端适配：实现虚拟摇杆、按钮组、右侧滑屏转视角、设置项（摇杆位置/透明度/按钮大小/震动反馈）。
5) 音频与美术：Three.js 程序化生成场景与材质；配乐由本地 AI 音乐生成脚本（scripts/generate-music.py，基于 MLX + MusicGen）生成后接入 Web Audio 播放系统（audio.ts）。
6) 测试与调优：用 Node 内置 test runner + TypeScript strip-types 直接对规则层做单元测试（7 个测试文件：game / experience / audio-playback / music-layout / lucky-rewards / new-gameplay / snow-footprints），npm test 全绿后逐关人工试玩调手感。

AI 与个人分工：
· AI（编程助手）完成：设计文档解读与代码骨架生成、渲染与交互模块的初版实现、移动端摇杆交互、测试用例编写、大量重构与 bug 定位、按需求文档逐项核对功能。
· 个人完成：核心玩法设计（凹坑窗口、减速带借势的数值手感）、关卡路线与坑位/陷阱布置、美术风格定调（低多边形 + 季节雾色 + 配色方案）、AI 生成音乐的人工筛选与混音、双端手感打磨与最终验收。

4. 问题与解决
真实问题：第 5 关「四季回响」终章在整合阶段出现性能与玩法双重问题——终章同时包含四季雾效、恶龙 BOSS、水火机关、坑阵与传送门，帧率在低端手机上明显下降；同时 BOSS 追击逻辑（chase.ts 的 CHASE_MAX_DISTANCE 超距判定）在玩家利用坑阵弹跳拉开距离时会错误触发，导致追击中断、战斗失去张力。

解决过程：
1) 性能：用 ctx 性能分析定位到雪脚印（snow-footprints.ts）全量几何体逐帧更新；改为脚印几何合并 + 只保留最近 N 个脚印的环形缓冲，绘制调用大幅下降；同时限制 renderer.setPixelRatio 上限为 1.75、雾外物件不投射阴影。
2) 玩法：把「超距即中断」改为「超距则恶龙加速回追 + 阶段性喘息窗口」（chase.ts 重写追击点插值逻辑），并在 BOSS 阶段机（rules.ts 的 bossPhase）中显式声明各阶段追击参数，交由单元测试锁定。

改进效果：低端手机帧率恢复流畅；终章战斗节奏恢复「压迫—喘息—再压迫」的设计预期。前后对比：修复前超距 10m 即脱战，修复后 30m 内持续压迫回追，且该行为被 tests/new-gameplay.test.mjs 中的用例固定，回归可自动发现。

5. 经验总结
可复用经验：
· 规则层与渲染层严格分离（纯 TS 模块 + 依赖注入），是「AI 写代码 + 自动测试 + 人工调手感」三者能并行推进的前提。
· 用 Node 原生 test runner + strip-types 直接测 TS，零额外测试框架成本，规则改动秒级回归。
· 手感类参数（坑跳窗口、体力消耗、追击距离）集中进 rules.ts 并配测试锁定，AI 重构时不丢设计意图。
· AI 生成内容（音乐）走「脚本化生成 + 人工筛选」流水线，prompt 与曲目配置入仓库可复现。

后续改进方向：
· 引入 AI NPC 对话/关卡旁白（接入 LLM 推理服务，让山中「隐者」按玩家进度给出提示或讲成语典故）。
· 关卡编辑器与玩家自制成语关卡分享。
· 更精细的移动端性能分级（画质档位）、手柄支持。
· 成就系统与云端存档。
